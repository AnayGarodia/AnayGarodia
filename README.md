# hi, I'm Anay

I'm a freshman at Columbia studying mathematics and computer science. I grew up in Kolkata, which means I had monsoons instead of snow days.

I'm interested in AI safety and I'm trying to learn it properly before I start pretending I know things. Right now that looks like building transformers from scratch, working through the ARENA curriculum, and reading more papers than is probably healthy for someone who also has a Lit Hum midterm on Dante.

I have a wandering problem. I'm building [agentweb](https://github.com/AnayGarodia/agentweb), which turns websites into fast CLI commands that any coding agent can use — no browser, no clicking, just typed operations against real sites. I've simulated neutron transport through fusion reactor blankets to find better tritium breeding materials. I'm training Kolmogorov-Arnold Networks on plasma data at Columbia's plasma physics lab. I built a browser automation agent called [Sisyphus](https://github.com/AnayGarodia/Sisyphus) because that felt appropriate, and a visual AI agent builder called [Dorian](https://github.com/AnayGarodia/dorian). At my first hackathon I built a real-time sign language translator that can join your Google Meet calls. I sometimes make math animations with Manim when I want to understand something badly enough to explain it to a render engine.

I play drums, read Wodehouse between problem sets, and think the most underrated skill in research is knowing when you're confused and admitting it out loud.

### open source

Over the last year I've had 100+ pull requests merged into projects I don't own, including [burn](https://github.com/tracel-ai/burn), [martin](https://github.com/maplibre/martin), [Daft](https://github.com/Eventual-Inc/Daft), [sqlglot](https://github.com/tobymao/sqlglot), [woodpecker](https://github.com/woodpecker-ci/woodpecker), [piccolo](https://github.com/piccolo-orm/piccolo), [typeguard](https://github.com/agronholm/typeguard), and Boeing's [config-file-validator](https://github.com/Boeing/config-file-validator). Mostly correctness fixes: race conditions, edge cases in linting rules, things that only break when a real user hits them. I think fixing a bug in someone else's codebase is the fastest way to actually learn how it works.
